***any***
In TypeScript, any helps avoid type errors, but it also removes TypeScript’s type safety.Normally, TypeScript can understand the type of a value automatically. This is called implicit typing or type inference.But when we use any that means this value can be anything, so don’t check its type.

As a result, TypeScript stops checking for type-related mistakes. If we use the wrong type or wrong operation, TypeScript will not show an error during development, but the application may crash at runtime.

<!-- Example -->
let word: any = ["T", "Y", "P", "E"];

console.log(word());

Here, word is actually an array.But we are trying to call it like a function using word().Normally, TypeScript would show an error.However, because word is declared as any, TypeScript allows it.

This will cause a runtime error like:
<!-- TypeError: word is not a function -->

So, using any too much is risky because it disables TypeScript’s type checking system.



***Unknown***
unknown is safer than any because it still performs type checking.Like any, the unknown type can store any kind of value.But unlike any, TypeScript does not allow us to use the value directly without checking its type first.So, before performing any operation on an unknown value, we must verify its type. This helps prevent runtime errors.

<!-- Example -->
let value: unknown = "TypeScript";

console.log(value.toUpperCase());

TypeScript will show an error because value is of type unknown.To use it safely, we need type checking:

let value: unknown = "TypeScript";

if (typeof value === "string") {
  console.log(value.toUpperCase());
}

Here, TypeScript knows that value is a string inside the if block, so the code becomes safe.

So:

any → disables type checking
unknown → allows any value but requires type checking before use

That’s why unknown is considered safer than any.
